# MiniMax H3 视频协议

该协议用于已接入容启上游的 MiniMax H3 异步视频任务。平台会按参考素材可访问性选择 JSON 或 multipart 请求，不把本地资源地址暴露给上游。

## 接口与鉴权

{{OPERATIONS}}

```http
POST {channel_base_url}/videos
GET  {channel_base_url}/videos/{task_id}
Authorization: Bearer <CHANNEL_API_KEY>
```

## 模型与能力

渠道模型标识由管理员在模型配置中维护，例如 `minimax_h3_768p` 或 `minimax_h3_2k`。影策将其作为 `model` 传给渠道；实际可用时长、分辨率、参考素材数量与内容审核结果，以该渠道账户已开通的模型能力为准。协议只提供异步“创建任务 - 查询任务 - 下载成片”的执行合同，不会替模型选择或价格规则作出猜测。

## 参数与限制

{{PARAMETERS}}

当前已验证：最多 9 张参考图、3 段参考视频和 3 段参考音频；首尾帧模式必须仅传 2 张图片；参考视频和音频最长 15 秒。时长由渠道模型能力约束，不能由本协议文档替代。

## 运行时说明

公网参考素材发送 URL，私有素材改用 multipart 上传。成功状态会优先下载上游结果 URL，失败时回退到任务内容端点；不会在浏览器或任务消息中保存渠道密钥。

## 官方与渠道说明

MiniMax H3 的具体字段、可用模型和计费规则应以已签约渠道提供的 API 文档和控制台为准。渠道地址与密钥由系统渠道配置保存，协议文档不会记录密钥、账户编号或可复用的签名信息。上游若调整响应状态或下载链接有效期，应同步更新渠道配置或该适配器，而不是让客户浏览器直连上游。
